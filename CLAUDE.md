# CLAUDE.md

The HotCodePush NG Native demo: the NG Native template app, Angular on Expo SDK 58, on `@hotcodepush/expo-ota-updates`, which proves the Expo SDK in an app whose JavaScript is not React.
Stack: TypeScript, Angular 22 rendered through React Native's Fabric by `@ng-native/platform`, Expo SDK 58 on React Native 0.88 with Hermes, Metro with the `@ng-native/metro` transform, Vitest with `@ng-native/testing`; the native projects generated by `expo prebuild`, the iOS one on CocoaPods, the Android one on Gradle.

## Layout

```
src/main.ts                  the entry file, which bootstraps the app
src/app/app.ts               the one screen
src/app/row.ts               a label and value row of the screen
src/app/updates.ts           the Updates service and the token that loads the SDK
src/app/version.ts           the VERSION label, changed before a release
src/app/app.test.ts          the screen under a stand-in SDK
app.json                     the app config: the name, the ids and the two config plugins
hotcodepush.json             the project's configuration, as `init` writes it; it names the demo's own app in the HotCodePush organization on production
metro.config.js              NG Native's Metro config, which `expo export:embed` runs too
ios/, android/               generated by `expo prebuild`, ignored by git, never committed
```

## Commands

| Command                          | Does                                                           |
| -------------------------------- | -------------------------------------------------------------- |
| `npm run lint`                   | Prettier                                                       |
| `npm run typecheck`              | the Metro config and `ngc`                                     |
| `npm test`                       | Vitest                                                         |
| `npm run prebuild`               | `expo prebuild --no-install`: the native projects, no pods yet |
| `npm start`                      | the development server, for the development build              |
| `npm run ios`, `npm run android` | `expo run:ios`, `expo run:android`: the debug build            |

Run `npm run fmt` before every commit.
The native builds, after `npm run prebuild` and `pod install` in `ios/`: `xcodebuild -workspace ios/HotCodePushDemo.xcworkspace -scheme HotCodePushDemo -configuration Release -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build`, and `./gradlew assembleRelease` in `android/`.
`ci.yml` builds the release configuration of both platforms on the lockfile's SDK, with `HOTCODEPUSH_OFFLINE=1`, and asserts that the `hotcodepush.json` each build wrote names an embedded bundle whose files are in the app with their recorded hashes.

## The wiring

No native file is committed, so none is edited by hand: a change to a native project is a change to a config plugin.
`app.json` lists two, and every prebuild applies them in order:

- **`@ng-native/metro`**, the framework's. It adds `SceneDelegate.swift` and the status bar hook on iOS and leaves `bundleURL()` in `AppDelegate.swift` as Expo's template writes it.
- **`@hotcodepush/expo-ota-updates`**, the SDK's. The Xcode phase "Create HotCodePush binary" and the `apply from` line at the end of `android/app/build.gradle` run the CLI's build step on what the build bundled. `AppDelegate.swift` and `MainApplication.kt` hand React Native the bundle the SDK serves.

Both orders produce the same files. The SDK's plugin found every anchor it looks for in the NG Native template unchanged.

## The SDK in Angular

`src/app/updates.ts` loads `@hotcodepush/expo-ota-updates` through an injection token whose factory calls `require()`, the pattern NG Native documents for an Expo module without a service of its own.
A static import would evaluate `react-native` when a test loads the file, which Node cannot parse, so the test provides a stand-in under the token.
The app uses the imperative `HotCodePush` API alone. The React hook `useUpdates` has no place here, since no React runs.

The build step writes `hotcodepush.json` into the app, the project's file plus `builtAt`, `fingerprint`, `embeddedBundleManifest` and `embeddedBundleId`. In a store build, an archive or a release variant, `binary create` also creates the store build's binary and needs a login or `HOTCODEPUSH_TOKEN`. Without one, or with `HOTCODEPUSH_OFFLINE=1`, the build names no channel and takes no updates.
A debug build bundles nothing and asks the development server for its JavaScript, so every sync answers `skipped` with `build_debug`. A first try of an update uses a release build.

## Dependencies

The SDK and the CLI are pinned to exact npm versions, `@hotcodepush/expo-ota-updates` and `hotcodepush`, bumped by Dependabot; the release workflow reads the CLI pin as `cli-version`, so one bump moves the native builds and the release together.
The `@ng-native/*` packages move together at one version, as the framework releases them.
Every other dependency is pinned as the NG Native template pins it.

## Comments

- Comment only what the code cannot say: the why behind a choice, an outside quirk or limit, what a regex matches, a TODO with its issue link. Never what the code does.
- Before adding a comment, try a clearer name or a small extracted function first.
- One or two short plain sentences. Capital letter, full stop, own line above the code. No run-on sentences, no chains of possessives.
- Doc comments (JSDoc, KDoc, `///`, docstrings) only on a package's public API: one line that says what it does, then only what a caller must know.
- Never: section banners, commented-out code, change history, the same comment in two places.

## Agent workspace

- `AGENTS.md` is the NG Native template's own file: the Angular side's rules, lowercase element names, imports and testing. Read it before a change to `src/`.
- `.claude/settings.json` enables the Expo plugin from the official marketplace, as the template ships it.
- `.claude/skills/` holds the developer skills copied from `hotcodepush-team/.github` with the skills CLI and pinned in `skills-lock.json`; update them with `npx skills update`.
- `.github/copilot-instructions.md` holds the review criteria, the only Copilot-specific file.
- Commits are conventional commits; `main` is trunk, CI is the gate, and a commit that lands an issue says `Closes #<n>`.
